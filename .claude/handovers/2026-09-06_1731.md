## 決定事項

- SPEC §5.4 に FR-M10〜FR-M15 を追加。§15 に P8〜P12 を追加し、段階 1 の積み残しの順序を明文化した。
- 内容ハッシュは crypto の SHA-256。大きさを 8 バイトで混ぜ、ブロック 2 つ分に収まるファイルは全体を読む。
- 対象キャッシュのスキーマを 3 に上げ、`contentHash` 列を足した（`addColumn` で移行）。
- 16 進ダンプはバイナリタグだけに出す。文字列・数値は生値の切替で足りるので行を増やさない。
  Isolate 境界を越えて運ぶのは先頭 512 バイトまで。
- 代表フレームの取り出しは再生器（Player + VideoController）を 1 つ使い回し、1 本ずつ通す。
- 地図の操作は地図の子として置く（カメラが動けば自分で作り直される）。置き場所は右下。
- 検索行は幅 900 未満で対象と範囲をメニューへ畳む（`SearchRow` 自身が LayoutBuilder で決める）。

## 捨てた選択肢と理由

- 代表フレームを 1 本ごとに Player を作って捨てる: `Player.dispose()` が返らず、
  2 本目以降が永久に止まった（実機で確認）。使い回しに変更。
- 開き直すだけで前の絵を掴まない前提: 実機で 3 本目（1 本目と同じ .mov）が
  2 本目の絵を返した。`open` の前に `stop()` を入れて解消。
- FR-M15 を「明度と彩度を落とす」で実装: 暗い地図として読めない。
  flutter_map の `darkModeTileBuilder`（色の反転）に変え、SPEC の文言も合わせた。
- ダンプをすべてのタグに出す（値の UTF-8 を出す）: 狭いパネルで行が窮屈になるのでやめた。
- 狭レイアウトで下端の帯にも「メタ情報」ボタンを置く: 下部ナビゲーションと二重になるので外した。
- 地図の操作を右上に置く: マーカーと重なり、まとまりを押せなくなる（テストでも露見）。右下へ移した。
- ホバーでの動画走査プレビュー（FR-B6 の一部）: 代表フレーム 1 枚の取り出しが重く、
  ホバーのたびに走らせると実用にならない。要否を実測してから決める（SPEC §15 P11 に明記）。

## ハマりどころ

- `flutter run -d macos` のビルドが数分かかる。release は特に長い（途中で打ち切った）。
  実機確認は debug で行い、パスは `--dart-entrypoint-args` で絶対パスを渡す
  （アプリの作業ディレクトリは当てにならない）。
- flutter_map の `MapOptions.onTap` は二度押しと見分けが付くまで発火しない。
  ウィジェットテストでは 500ms 進めないと拾えない。
- `Container(color:)` は当たり判定を持つ。地図の出典表示の上を押すと地図に届かない。
- flutter_riverpod は `Override` 型を公開していない。テストの引数に取れないので、
  必要な値を受け取って中で override を組み立てる形にした。
- `ThumbnailCache.peek` が「読めなかった」記憶（値 null）まで消していた（既存の不具合）。修正済み。

## 学び

- media_kit は既定で `vid=no`。`VideoController` を付けて初めて 1 枚取り出せる。
- crowexif の `TagEntry` は `value`（変換前）と `printValue`（表示用）を両方持ち、
  `binaryPlaceholder` に実バイトが入る。FR-V3 はこれで賄える。
- 実機確認用の一時的な入口（`tool/verify_poster_frame.dart`）を作って
  `flutter run -t` で回すと、ヘッドレスで確かめられないネイティブ依存を検証できる。使い終わったら消す。
