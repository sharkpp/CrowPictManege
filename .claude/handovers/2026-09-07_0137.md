## 決定事項

- 地図の操作は 2 つに分けた。見方を変えるもの（位置を決める・トレイ・絞り込み・軌跡）は
  右上へ横に並べ、動かすもの（拡大・縮小・北・全体）は右下に残す。縦に積むと右端が
  塞がり、その裏のマーカーを押せなくなる（テストでも露見した。前回の「右上に置くと
  マーカーと重なる」の逆で、横 1 列なら上端の帯だけで済む）。
- 地図へ落として位置を付ける操作は、選択集合の全体へ配る `SetLocation` とは別の
  `PlaceAsset`（当てる相手を自分で持つ）にした。落とし先は対象ごとに違うので、
  1 つの操作を全員に配る形では表せない。`EditTarget` に `path` を足した。
- 表示範囲での絞り込みが効いている間は、地図の寄せ直し（`_refit`）を止める。
  動かせば絞りが変わり、絞りが変われば出る対象が変わって、いつまでも落ち着かない。
- 範囲を拾うのは地図が落ち着いたとき（`MapEventMoveEnd` など）だけ。1 コマごとに
  絞り直しては 10 万件の一覧が付いてこられない。
- トラックログの突き合わせは、積むのは「この記録から取り込む」という 1 つの操作とし、
  当たる位置は適用のときに対象ごとに決める。時刻を直す操作より後に積めば、直した
  あとの時刻で引く（`planEdits` が順に畳むので自然にそうなる）。
- crowexif の `GpsTrack.at` に `maxDistance` を渡せるようにした（既定は 30 分のまま）。
  点の間隔は記録の仕方で桁が違うので、許容差はアプリが決める。
- 動画の書き込みは movie box だけを組み直し、それ以外の箱は読んだままのバイトで運ぶ。
  ヘッダが伸びた分だけ chunk offset（`stco` / `co64`）を動かす。movie box より前に
  ある値は動かさない。これで faststart のファイルでも壊れない。
- 動画の位置は `©xyz` と Apple の位置キー（`com.apple.quicktime.location.ISO6709`）の
  両方へ書く。2 か所が食い違うと読み手によって答えが変わる。ただしキーの表を
  持たないファイルには表を作らない（無かった形の metadata box を生やさない）。
- 動画のヘッダはオフセットを持てないので、時刻は UTC の瞬間に畳んで書く。書き戻しの
  検証も、壁時計の表記ではなく瞬間で見るようにした（FR-E6-3）。
- 転送先（FR-T3）は「実行ファイル＋引数のひな型」で持ち、設定へ JSON で残す。
  値に何が入るか分からないので区切り文字の符号化はしない。
- 書き出し（FR-T6）で同じ名前があれば連番を足す。上書きはしない。衝突方針を選ばせるのは
  仕分け（段階 4、FR-S4）の仕事とする。
- 地名の検索と逆引きは既定で止め、設定で「何が外へ出るか」を添えて選ばせる（NFR-5）。
  切ってあるときも検索欄は隠さず、理由を添えて押せない状態で出す。
- 逆引きは丸めた座標（小数 4 桁）を鍵にして持っておき、同じ場所を何度も引かない。

## 捨てた選択肢と理由

- ピンのドラッグを `GestureDetector(onPanUpdate:)` で受ける: 地図の
  `ScaleGestureRecognizer`（チームの captain）が勝ち、ピンが動かなかった。生の
  `Listener` で受け、掴んでいる間だけ `InteractionOptions.flags` を `none` にして
  地図を止める形にした。flutter_map は毎回の update で drag フラグを見るので、
  掴んだ後にフラグを変えても効く。
- 落とした対象の位置を即座にファイルへ書く: 適用前の見通し（FR-E5）を飛ばすことになる。
  積むだけにして、適用は編集の作業面から行う。
- 地図の表示範囲の絞り込みから地図自身を外す（一覧だけ絞る）: 実装は楽だが、
  「いま見えているものだけ」という意味が地図と一覧で食い違う。地図も同じ絞りに従わせ、
  代わりに寄せ直しを止めることで落ち着かせた。
- 外へのドラッグ（FR-T4）を super_drag_and_drop で入れる: 現在の Flutter（3.44）に
  対して壊れており（`HitTestResult` の受け取り方が変わっている）、取り込むとテストも
  ビルドも通らない。依存を外し、SPEC §14 の未決事項に残した。
- 動画の位置読み取りを crowexif の Composite で行う: exiftool 互換のテストがある層に
  新しい派生値を足すことになる。アプリの `normalizeLocation`（もともと「正規化した位置」を
  作る場所）で ISO 6709 を読む形にした。
- 動画の keys / ilst を新しく作れるようにする: 表の無いファイルに metadata box を
  生やすと、そのファイルが元々持っていなかった形を勝手に決めることになる。
  既にある表への追記だけを認める。
- `dart format` を crowexif にかける: 75 ファイルが書き換わった。crowexif は
  Dart 3.7 より前の整形のままなので、**crowexif では dart format を走らせない**。
  今回は `git checkout` で戻し、自分の変更だけを当て直した。

## ハマりどころ

- crowexif で `dart format lib test` を走らせると、リポジトリ全体が新しい整形（tall style）に
  書き換わる。差分が 75 ファイルに膨れ、自分の変更が埋もれる。走らせないこと。
- ARB のメッセージに `{files}` のような波かっこを地の文で書くと、プレースホルダとして
  解釈されて引数付きの関数になる。置き換えの語そのものを見せたいときは、
  `{all}` のような別名のプレースホルダにして、呼ぶ側から `'{files}'` を渡す。
- `find.widgetWithText(TextField, '分')` は、単位を `suffixText` に持つ別の欄にも当たる。
  同じ言葉が複数の欄に出る画面では `Key` で狙う（`shift-minutes` などを足した）。
- 設定を変えるウィジェットテストは、保存の遅延（400ms）を進めないと
  「A Timer is still pending」で落ちる。`catalogProvider` をメモリ上の drift に
  差し替えたうえで 500ms 進める。
- `dart format` は行を組み直すので、python で当てた置換の直後にもう一度同じ形で
  置換しようとすると当たらない。整形の前に全部当てるか、当てた後に `grep` で確かめる。
- `tool/capture.dart` は、フォルダが開けていなくても黙って同じ画面を撮り続ける
  （12 枚が同じバイト数になって初めて気付いた）。読めなかったら止めるようにした。
  1 回目の実行では原因が分からなかったが、2 回目は同じ引数で開けた。競合の疑いがある。
- `flutter test` はこの規模で 80 秒ほどかかる。`Bash` の既定 2 分の枠に収まらないことが
  あるので、テスト全体を回すときは timeout を伸ばす。

## 学び

- flutter_map の `MapCamera` は `latLngToScreenOffset` / `screenOffsetToLatLng` を
  持ち、回転を含めて往復できる。指の移動量（`event.delta`）を足して戻せば、
  ピンを地図の座標系で動かせる。
- `Marker.alignment` は「その位置に対してマーカーをどちら側へ置くか」で、
  `Alignment.topCenter` にすると点の**上**に出る。先が下にあるピン（`Icons.place`）は
  これで先端が座標を指す。
- `DragTarget.onAcceptWithDetails` の `offset` は掴んだウィジェットの左上。指の位置を
  取りたいなら `Draggable` 側で `dragAnchorStrategy: pointerDragAnchorStrategy` を使う。
- ISO BMFF は `stco` / `co64` が絶対オフセットなので、movie box の大きさが変われば
  そこを直さないと再生できなくなる。逆に mdat が movie box より前にあるファイル
  （今回の fixture はどちらもそう）は直す必要がない。
- crowexif の HEIF 書き込み（`heif_edit.dart`）は同じ箱の木を扱うが、item 中心の
  構造なので動画とは別物。動画は `iso_bmff_edit.dart` として分けた。
- iPhone の動画は `keys` / `ilst`（`com.apple.quicktime.*`）に位置や機材を書く。
  crowexif はこれを読んでいなかったので、今回の読み取り追加で機材名なども出るようになった。
