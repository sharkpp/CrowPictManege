## 決定事項

- プラットフォームの違いは `lib/platform/platform.dart` の 1 か所に集める。
  画面と業務ロジックはこの口だけを見る。`dart:io` に触る実装も、ブラウザの API を
  呼ぶ実装も、その後ろに隠す。
- できないことは能力フラグで表し、画面からは隠さずに理由を添えて無効にする
  （SPEC §8）。フラグは「何ができるか」で名付け、プラットフォーム名では分けない。
- 「パス」は取得元が対象を引くための鍵として扱う。Web ではディレクトリハンドルを
  引く鍵であって、ファイルシステム上の位置ではない（SPEC §4.5）。
- 取得元は 1 つだけ持つ。選ぶ側と走査する側で実体が分かれると、選んだフォルダを
  走査できない（実際にこの取り違えを作って直した）。
- 知覚ハッシュは 16 進 16 桁の文字列で持つ。64 ビット整数のままではブラウザで
  上位が落ちる。キャッシュの形は v4 へ上げ、前の形の値は読み替えず作り直させる。
- Web では原本の控えを取らない。ブラウザにはアプリ領域が無く、利用者のフォルダへ
  勝手に控えを置かない。控えを取れない環境では、設定も取り消しも出さない。
- スレッドが 1 本しか無い環境には走査の上限（2 万件）を設ける。打ち切ったことは
  状態の帯に出し、走査はいつでも中断できる（SPEC §7.3）。
- 別スレッドへ逃がす処理は `Isolate.run` ではなく `compute` を使う。Web には
  別スレッドが無く、同じ書き方のまま「その場で行う」へ落ちる。

## 捨てた選択肢と理由

- `dart:io` を使う場所ごとに `kIsWeb` で分岐する: 分岐が散らばり、Web 向けの
  組み立てでは結局コンパイルできない（`dart:io` の実装が無い）。条件付き取り込みで
  「そもそも取り込まない」形にした。
- Web でも控えを取るために、利用者のフォルダへ `.backups/` を作る: 頼まれていない
  ものを利用者のフォルダに置くことになる。控えは取らないと決め、取り消しも出さない。
- 知覚ハッシュを BigInt で持つ: 桁は合うが、カタログの列と比較の両方が重くなる。
  16 進の桁で持てば、保存も比較も 32 ビットずつで済む。
- `flutter run -d chrome` を画面操作の自動化（System Events）で動かして
  フォルダ選択まで確かめる: 利用者の実画面を押すことになる。途中でやめた。

## ハマりどころ

- `dart2js` は `dart:io` の取り込み自体は通す（使うと実行時に落ちる）。
  「Web 向けに組み立てが通る」ことは「Web で動く」ことを意味しない。
  能力フラグと条件付き取り込みで、実際に呼ばない形にしておく必要がある。
- ブラウザ向けのテスト（`flutter test --platform chrome`）で初めて分かる食い違いが
  ある。知覚ハッシュの 32 ビット切り捨てはこれで見つかった。Web を触ったら
  `test/domain` だけでも Chrome で走らせること。
- File System Access API の一覧は JavaScript の非同期反復子で返る。`package:web` は
  `values()` を持たないので、`next()` を 1 つずつ待つ小さな extension type を自分で書く。
- drift の Web は `sqlite3.wasm` と `drift_worker.js` を配布物に含める必要がある
  （`web/` に置いた。drift のリリースから取る。版を上げたら差し替えること）。
- `super_drag_and_drop` の依存（irondash）は macOS 12 以上を要求する。
  `MACOSX_DEPLOYMENT_TARGET` と Podfile の両方を 13.0 へ上げた（SPEC §2 の宣言に合わせた）。
- `Notifier.build()` の中で `state` は読めない（初回は未設定）。

## 学び

- 条件付き取り込み（`export 'a.dart' if (dart.library.js_interop) 'b.dart'`）は
  「どちらの側にも同じ名前と同じ型がある」ことが前提になる。片方だけ非 null に
  すると、もう片方向けに書いた呼び出しが通らない。返り値の null 許容は揃える。
- `compute` は Web でその場で走る。`Isolate.run` の置き換えとしてそのまま使える。
- FSA の `createWritable()` は一時ファイル経由で置き換える。SPEC FR-E6-1 が求める
  「半端なファイルを残さない」書き込みが、ブラウザ側の実装として既にある。
